# 2026-08

## 2026-08-20 — repository opened

**Changed:** first public commit. The library (`packages/extrct`) is the engine that
grew out of a private research stack, extracted and restructured: a provider registry
(ollama, openrouter) behind one contract, XAI as pure analysis over stored evidence
(`xai.certainty`, `xai.grounding`), the run log behind a `RunStore` protocol with
Postgres and SQLite backends, a `job-def/1.0` YAML contract with the `Extractor`
facade, and optional OpenTelemetry. Alongside it: the Langflow integration
(`integrations/langflow/`), the compose stack (`deploy/`), and the design of record
(`docs/extraction-stack/`) that explains what was measured and why the code defends
against it.

**Verified:** 209 offline tests pass on Windows, macOS, and Linux in CI (no model, no
key, no network — mock transports and synthetic payloads shaped like real provider
responses); the offline demo runs the full pipeline end-to-end including grounding,
certainty, and the SQLite run log; `uv build` produces a clean sdist and wheel; the
compose manifest resolves; the library contains no Langflow import.

**Learned:** two things worth keeping. Moving a bind-mount source while a container
runs is silent — Docker resolves host paths at container creation, so the canvas kept
running against directories that no longer existed, with no error anywhere; any path
change under `deploy/components/` needs `--force-recreate` and a `docker inspect`
check. And a "cleanup" regex that collapses runs of whitespace will eat Python
indentation and empty call parens: text transformations over a source tree need a
syntax check afterwards, not a diff skim.

**Open:** publishing 0.1.0 to PyPI; migrating the Langflow components off the frozen
legacy engine onto the published package; the vLLM provider. See TODO.md.

## 2026-08-20 — CI fixed after the first push failed; setup guides added

**Changed:** `.github/workflows/ci.yml` and `release.yml` no longer use
`uv pip install --system`; every job creates a project venv (`uv venv` +
`uv pip install`) and runs through `uv run --no-sync`, and the release twine check
became `uvx twine check`. `packages/extrct/tests/test_certainty.py` widened the
enum-posterior sum tolerance from `1e-6` to `5e-6` with the rationale in a comment.
New setup guides (index, `01-library.md`, `02-langflow-stack.md`) under
`docs/for-user/setup/`. A PyPI Trusted-Publishing runbook was authored, used by the
maintainer to link the repo (pending publisher + the `pypi` environment restricted to
`v*` tags, no stored secrets), then removed at the maintainer's request once the
linking was done — the per-release essentials remain in `release.yml`'s header; pointers added in
`README.md` and `TODO.md`. `docs/` reorganised by audience: `for-user/` (setup),
`system-arch/` (extraction-stack, log, reference), and `for-amir/` (personal notes,
gitignored, local-only) — every repo reference updated, including the components'
`documentation:` strings and the frozen legacy engine's docstrings (path text only,
no behaviour change; syntax-checked after the substitution). Paths in entries above
this one predate the reorganisation.

**Verified:** the first CI run on GitHub (`3fcd6e9`) failed 7 of 8 jobs. Both causes
reproduced locally, then re-tested after the fix: 209 tests pass on CPython 3.10,
3.12, and 3.13 on Windows; a fresh-directory simulation of the exact CI sequence with
`UV_PYTHON=3.13` passes install → pytest → offline demo → `pip-licenses` scan (the
dependency tree is MIT/BSD/Apache/PSF/MPL only — nothing in the fail-on list); both
workflows parse as YAML. NOT yet verified: the same steps on GitHub's runners — that
needs the push.

**Learned:** two things. (1) `setup-uv` with `python-version:` installs a uv-managed
interpreter that refuses `--system` installs as externally managed — and on Windows
the failure was masked: the install landed in one interpreter while `python` resolved
another, so the *test* step failed instead of the install, making one bug look like
two. (2) The certainty test asserted the enum posterior sums to 1.0 within `1e-6`,
but each member is independently rounded to 6 dp — worst case for 3 options is
exactly 1.5e-6, so the bound sat on the boundary and flipped with the interpreter
build (3.10 failed, 3.12/3.13 passed). A tolerance that equals the worst-case error
is a coin flip, not a bound.

**Open:** push and confirm the matrix goes green on GitHub; then the release dry run
(Actions → release → Run workflow) and the `v0.1.0` tag — the PyPI side is already
linked.

## 2026-08-20 — CI green on GitHub; model registry; GPU-host guide

**Changed:** `ci.yml`/`release.yml` moved from `uv venv` + `uv pip install` to
`uv sync --extra dev` (+ `uv pip install --python .venv` for pip-licenses). New
`extrct.models` — the model registry, contract `model-registry/1.0` — wired into
`__init__`, with `tests/test_models.py` (230 offline tests total) and a live probe
battery `examples/08_model_probe.py` that prints paste-ready entries. Root README
gained "Why a new library?" (vision: hierarchical extraction, interpretability,
local-first, scale; clinical-first, governance-first). New
`docs/for-user/setup/03-add-gpu-host.md` (LAN-cable and overlay wiring for a GPU
host). CHANGELOG `[Unreleased]`; providers.md points at the registry.

**Verified:** run 32379905374 — all 8 CI jobs green on GitHub. The first fix attempt
(venv + uv pip) failed on runners: setup-uv exports `VIRTUAL_ENV` at the repo ROOT,
`uv pip install` honours it while `uv run` uses the project venv under
`packages/extrct` — two different environments; `uv sync` ignores a mismatched
VIRTUAL_ENV by design (reproduced locally with a decoy VIRTUAL_ENV before pushing).
OpenRouter's public model list confirms `google/gemma-4-31b-it` (+ `:free`). The DGX
Ollama (0.32.14) is reachable over the tailnet with the gemma4 31b family pulled in
four quants. After the DGX came up (2026-08-21, past midnight): the probe battery
measured `gemma4:31b-it-q4_K_M` at 5/5 pass - hierarchical structured output,
certainty (pre_mask), enum posterior, grounding (4 exact quote alignments), 2-chunk
long-text merge - ~10 tok/s warm, fully in VRAM; the measured rows are now in
`models.py`. First probe run reported enum_posterior as fail: a probe bug (the
`_evidence.*` mirror row shadowed the real field), fixed and re-run.

**Learned:** (1) setup-uv with `python-version:` both manages the interpreter AND
activates a venv at the repository root — `uv pip install` and `uv run` then resolve
*different* environments when the project lives in a subdirectory; `uv sync` is the
one primitive that deterministically targets the project's own `.venv`. (2) An
Ollama host that answers `/api/tags` can still drop `/api/chat`: GPU contention (a
vLLM model load) presents as TCP-level resets on generate paths, not as HTTP errors.

**Open:** `OPENROUTER_API_KEY` for the openrouter probe lane; other gemma4 quants
and providers as they land; then component migration.

## 2026-08-21 — mini-app lane: design of record

**Changed:** new `docs/system-arch/workbench/mini-apps.md` — design of record for
`apps/` mini apps: Streamlit-only lane, one compose component per app under
`deploy/components/` behind `profiles:` on `127.0.0.1`; two rules mirroring the root
red lines (zero extraction/schema logic in apps; app output is an artifact of
record); proposed `annotation-def/1.0` as the output handshake (content uid, values
validated against the exact `schema_uid` schema, timestamps ride the row not the
hash); requirements for the first app (human extraction form rendered from a
variables set, three-state widgets for optional bools under `strict_nullable`).
`docs/README.md` gained the `workbench/` folder in the system-arch row; the `apps/`
bullet in `TODO.md` now links the design doc.

**Verified:** nothing executed — this entry lands a design document only. The
Streamlit constraint it records (no dynamic add-row inside `st.form`, so nested
list-of-objects needs `st.data_editor` or manual `session_state`) is from Streamlit's
documented form semantics, not measured here; the doc flags it as the
prototype-first risk.

**Learned:** the main-UI/mini-app split falls directly out of Streamlit's
whole-script-rerun model: it disqualifies the data-heavy, push-notification
workbench and is nearly ideal for one-screen schema-driven forms — so the framework
decision is per-lane, not per-project. The human-form app will be the first UI
surface that legitimately displays real clinical text (Langflow never may), which
tightens its deployment posture rather than relaxing it.

**Open:** three questions listed in the doc for review before the first app lands —
where `annotation-def/1.0` rows are stored, the pseudonymous annotator id scheme,
and whether the contract module enters `packages/extrct` with the first app.

## 2026-08-21 — lane framework revised to NiceGUI; apps/ split into mini/ + workbench/

**Changed:** framework decision for the mini-app lane revised from Streamlit to
NiceGUI before any app code — `docs/system-arch/workbench/mini-apps.md` rewritten
with a "Framework revision" section recording why (maintainer's firsthand Streamlit
failures: session-state desync and form snap-back in dynamic forms — the exact
prototype-first risk the original decision named). `apps/` restructured into lanes:
`apps/mini/` (mini apps + `_template/`, lane rules in `apps/mini/README.md`) with
`apps/workbench/` reserved for the main UI; `apps/README.md` is now the umbrella
index. Template converted: `nicegui>=3.16` (+ `nicegui[native]` note), `app.py`
builds inside `@ui.page('/')` with host/port from env (127.0.0.1 default),
Dockerfile CMD `python app.py` on port 8080, `.gitignore` swaps
`.streamlit/secrets.toml` for `.nicegui/`, `.streamlit/config.toml` deleted.
`[tool.uv.sources]` path deepened one level.

**Verified:** handshake tests re-run and pass (system python3); all TOMLs/JSON
parse, `app.py` compiles; no stray Streamlit references outside the deliberate
decision history. Two research agents (official docs/source + community record)
reported 2026-08-21; key measured facts, from their reports: NiceGUI 3.16.0
(2026-08-12, MIT, Zauberzeug) has NO telemetry (source grep of the installed
wheel; assets served from the wheel, opt-in On Air is the only remote path) while
Streamlit 1.62.0 ships usage stats ON by default; `ui.run` host defaults to
0.0.0.0 in non-native mode; NiceGUI 3.0 (2025-10) removed the shared auto-index
page; `nicegui-pack` (PyInstaller) is the documented desktop packaging path and
requires `reload=False` + a page function; validation is first-class on
input/number/select/textarea/input_chips; `bind_value` reaches nested keys via
string tuples. Community record: Streamlit→NiceGUI migration accounts repeatedly
cite session-state pain, no reverse migration found; Streamlit has paused external
PRs (README, verified); `streamlit-pydantic` last released 2023-03; `nicecrud`
(MIT) generates NiceGUI forms from Pydantic models incl. nested — flagged in the
design doc as the reference to evaluate before hand-rolling.

**Learned:** (1) NiceGUI's `ui.run` default host is 0.0.0.0 — the template's
explicit APP_HOST=127.0.0.1 default IS the localhost rule's enforcement point.
(2) Module-level widgets were a cross-session state leak and are gone in 3.x —
always build under `@ui.page`. (3) The app-folder tests and `data_model.json`
survived the framework swap untouched — evidence the handshake sits at the right
altitude.

**Open:** unchanged (annotate instantiation gated on the three design questions;
Dockerfile buildable after the PyPI release). New: pin `nicegui` exactly when the
first app locks, given the project's ~annual major-bump cadence.
